# BGM Filter · 需求规格（V1）

> 本文档是需求与验收的唯一依据。开发者遇到歧义时以本文档为准；实现细节见 `docs/architecture.md`。
> 项目定位：**本地个人工具**，读取 `dump-db/` 下的 Bangumi Archive 数据导出，在网页上按条件筛选条目并浏览结果。

## 1. 目标与背景

Bangumi 全量条目数据（约 70 万条）以 JSONL 形式存放在本地 `dump-db/`。现有数据没有便捷的「按标签组合 + 年代筛选 + 评分排序」浏览方式。V1 要交付一个本地运行的网页工具：

- 全量数据**一次性导入**本地 SQLite（`prisma/dev.db`），之后筛选为毫秒级；
- 单页交互：顶部筛选区，下方结果区，筛选条件实时反映在 URL 上（可复制分享、刷新保留）；
- 使用 **T3 Stack**（Next.js App Router + TypeScript + tRPC + Prisma + Tailwind CSS），用 **pnpm** 维护依赖；
- 纯本地使用，**无登录 / 无账号 / 无外部服务**。

## 2. 数据事实（来自实际 dump，2026-11-03 抽样统计）

数据源：`dump-db/subject.jsonlines`，UTF-8（无 BOM），700,108 行，约 993 MB，每行一个 JSON。字段定义见 `dump-format.md`。

| 指标 | 数值 | 对需求的影响 |
| --- | --- | --- |
| 条目总数 | 700,108 | 必须分页 |
| 按类型 | 漫画 422,971 / 动画 31,258 / 音乐 101,230 / 游戏 117,881 / 三次元 26,768 | 提供类型筛选（默认全选） |
| 有用户标签 `tags` | 348,536（49.8%） | 只用 tags 会有大量条目筛不到 |
| 有公共标签 `meta_tags` | 235,232（33.6%） | 与 tags 合并后覆盖 422,912（60.4%） |
| 有评分 `score > 0` | 287,448（41.0%） | 59% 条目无评分，排序需单独处理 |
| 有排名 `rank > 0` | 43,604（6.2%） | 仅展示，不参与 V1 排序 |
| 日期为空 | 53,871（7.7%） | 年代筛选需容忍无日期条目 |
| 日期格式 | 全部 `YYYY-MM-DD`（有 14 条 `YYYY` 为 4 位但形如 `0701` 的脏数据，以及少量 <1900 / >2032 的异常年份） | 取前 4 位数字作为年份；年代筛选按数值比较 |
| 标签总数（tags ∪ meta_tags 去重后） | 92,878 | 需要标签联想/常用标签 |
| `name_cn` 缺失 | 552,686（78.9%） | 展示时回退到 `name` |
| 含空格或 DSL 元字符的标签名 | 35 个含空白字符；624 个含 `& \| ( ) ! ~`；0 个含引号 | 标签 DSL 必须支持引号包裹 |
| 大小写不同的同名标签 | 914 组（如 `galgame` / `Galgame`） | 标签匹配大小写不敏感，展示用规范名 |

其他：`tags` 是 `[{name, count}]`（用户标签，按热度排序，可能为空数组）；`meta_tags` 是 `string[]`（公共标签，可能为空数组）；`favorite` 是 `{wish,done,doing,on_hold,dropped}`；`score_details` 是 1–10 分的人数分布。dump 中**没有封面图**，结果卡片只能用文字信息。

## 3. 功能需求

### F1 多标签筛选（标签表达式 DSL）

- 筛选区提供一个标签表达式输入框，语法：
  - 标签 = 标签名（大小写不敏感，精确匹配，匹配对象 = 用户标签 ∪ 公共标签）；
  - `&` 且、`|` 或、`!` 或 `~` 取反、`()` 分组；
  - 优先级：`!`/`~` > `&` > `|`，括号可覆盖；空白仅作分隔；
  - 标签名含空白或 `& | ( ) ! ~ "` 时必须用双引号包裹，如 `"C&C"`、`"|Otome|"`、`"K-ON!"`；引号内支持 `\"` 与 `\\` 转义；
  - 空表达式 = 不限制标签。
- 示例：`科幻 & (恋爱 | 百合) & !R18`、`"C&C" | "D&D"`。
- 输入框下方实时给出解析状态：合法时显示「当前表达式涉及 N 个标签」；非法时在输入框下方红字提示错误原因与字符位置（如「第 12 个字符附近缺少右括号」），**不要**让整个页面报错。
- 自动补全：输入标签名时展示下拉候选（标签名 + 条目数，按条目数降序，最多 20 个），点击候选将**已正确转义/加引号**的标签文本插入光标处。
- 常用标签快捷插入：展示按条目数排序的常用标签（如 漫画、游戏、PC、日本、R18…），点击即插入表达式。
- 不存在的标签不算语法错误：结果为空并给出提示「未知标签：xxx」（列在结果摘要处）。

### F2 年代筛选（与标签条件是 AND 关系）

- 提供「起始年 / 结束年」两个输入（整数，含边界，范围 1000–2100，允许留空 = 不限）。
- 只填起始或只填结束均合法；起始 > 结束时给出前端提示且不发起请求。
- 无发行日期的条目在设置年代条件后**不出现**在结果中（属于正确行为）。
- 与标签、名称搜索、类型筛选全部是 AND 关系。

### F3 作品类型筛选

- 类型多选：漫画(1)、动画(2)、音乐(3)、游戏(4)、三次元(6)，默认全选；全部取消等价于全选。
- 每个类型旁展示该类条目数（来自 `stats` 接口）。

### F4 名称搜索

- 输入框按 `name` 或 `name_cn` 大小写不敏感子串匹配（转义 `%` `_`），与其它条件 AND。
- 去首尾空白，最长 100 字符；空串 = 不限制。

### F5 评分排序

- 排序开关：`综合评分`（默认，贝叶斯加权 `(score*scoreVotes + C*m)/(scoreVotes+m)`，C 为全局按人次加权平均分、m=50，弱化小样本刷分）/ `评分从高到低`（原始 score）/ `评分从低到高`（原始 score）。
- 「无评分条目位置」开关：`置底`（默认）/ `置顶`（只影响 `score = 0` 的条目；同分/同组时按 `id` 升序稳定排序）。
- 结果总数、当前页、每页 50 条、总页数。

### F6 分页

- 固定每页 50 条；上一页/下一页 + 页码（首页、末页、当前页 ±2）；越界页由服务端夹到有效范围。
- 切换筛选条件时页码重置为 1。

### F7 URL 状态

- 单页应用，筛选状态写入 URL query，刷新/复制链接可还原：
  `/?tag=<表达式>&q=<搜索词>&types=1,2,3,4,6&from=1990&to=2005&sort=score_desc&scoreless=last&page=2`
- 默认值省略（不写入 URL）；非法参数回退默认值；筛选变更 debounce（约 300ms）后写入 URL 用 `router.replace`。
- 浏览器前进/后退能还原筛选状态。

### F8 结果卡片

每条结果展示：

- 封面图（左侧，2:3 比例）：来自 Bangumi 官方 API 解析出的 `lain.bgm.tv` 直链，浏览器直接加载、服务端只缓存 URL；**所有条目（含 `nsfw`）均加载封面**；仅官方无图或加载失败时显示等比例灰底占位「无封面」，**不得出现裂图**；
- 评分 `score`（保留 1 位小数；`score = 0` 显示「无评分」）与评分人数 `scoreVotes`，位于标题下方 meta 行（形如 `9.4 · 7,154 人评分`）；
- 主标题：`name`；副标题：`name_cn`（存在且与 `name` 不同时）；均支持长文本截断 + `title` 悬浮完整文本；
- 类型徽标（漫画/动画/音乐/游戏/三次元）；`nsfw` 条目不额外提示、封面照常显示（V1 不做 NSFW 过滤）；
- 年份/日期：`date` 原值或 `year`；
- `rank`（>0 时显示「#1933」样式）；
- 标签：最多 8 个（用户标签优先，其次公共标签），点击标签把该标签**追加**到当前标签表达式（自动处理 `&`、引号、去重）；
- 「看过」人数（`favorite.done`，来自 dump 的 favorite 字段）；
- 整卡链接到 `https://bgm.tv/subject/{id}`，新窗口打开（`rel="noreferrer"`）。

### F9 状态与空态

- 加载中：结果区骨架屏（不要页面跳动）。
- 无结果：显示「没有匹配的条目」+ 若干宽松化建议（清空标签 / 放宽年代 / 取消名称搜索），并给出当前条件摘要。
- 接口/数据缺失错误：可读错误信息（例如数据库未导入时提示运行 `pnpm db:import`），不要让白屏。

### F10 数据导入（命令行）

- `pnpm db:import` 从 `dump-db/subject.jsonlines` 生成/覆盖 `prisma/dev.db`，导入完成后打印统计（条目数、标签数、关联数、耗时、文件大小）。
- 可重复执行（幂等：导入前重建表/清空）。默认路径 `dump-db/`，可用 `DUMP_DIR` 环境变量覆盖。
- 应用运行时只读 DB，不再扫描 JSONL。

## 4. 非目标（V1 明确不做）

- 登录注册、多用户、云端部署与鉴权（T3 的 NextAuth 不启用）；
- 条目详情页、章节/人物/角色数据（其它 dump 文件 V1 不导入）；
- 封面图片、评分分布图、评论；
- 按 `meta_tags` 单独筛选、按排名/日期排序、二次筛选、条件收藏/导出；
- 移动端专门优化（但布局需在窄屏可用）。

## 5. 非功能需求

| 项 | 目标 |
| --- | --- |
| 导入耗时 | 单机 ≤ 5 分钟（700k 条目 + 2,267,357 标签关联；实测 19.5 s） |
| DB 体积 | ≤ 600 MB |
| 查询性能 | 典型条件（1–2 个标签 + 年代 + 类型）首屏 ≤ 300 ms；标签联想 ≤ 100 ms |
| 启动 | 已导入 DB 时 `pnpm dev` 即可用，无需重新导入 |
| 代码质量 | `pnpm typecheck` 与 `pnpm test` 全绿；关键 DSL 解析/编译有单元测试 |
| 可维护性 | DSL 语法/求值、查询构造、UI 分层；新增筛选条件不改动解析器核心 |
| 隐私 | 全程离线，无遥测；不联网请求第三方 |

## 6. 验收清单（QA 必须逐条验证）

1. `pnpm install` → `pnpm db:generate` → `pnpm db:import` → `pnpm dev` 全流程可复现，README 命令准确。
2. 页面默认加载：共 700,108 条，第一页 50 条，按评分降序，无评分条目排在最后。
3. 表达式 `科幻` 返回非空结果；`科幻 & 百合` 是 `科幻` 结果的子集；`(科幻 | 奇幻) & !R18` 结果同时满足语义；`"C&C"` 能命中该标签（若该标签存在）；`科幻 &&` 返回可读语法错误（HTTP 层不 500）。
4. 年代 2010–2020 结果全部 `year` 在 [2010, 2020]；与标签组合后结果仍满足两个条件。
5. 类型只勾选「动画」时结果全部 `type = 2`；全部取消勾选等于全选。
6. 名称搜索「攻壳」能命中相关条目。
7. 排序切换后第一页顺序符合预期；「无评分置顶」时第一页全部 `score = 0`。
8. 分页：第 2 页与第 1 页无重复；末页条目数正确；越界页码被夹取。
9. URL 复制到新标签页后筛选状态一致；清空筛选后 URL 无冗余参数。
10. 结果卡片链接、标签点击追加表达式、常用标签插入、自动补全均可用。
11. 空态/错误态（例如临时改 `DATABASE_URL` 指向不存在 DB）有可读提示。
12. 标签表达式解析器单元测试覆盖：优先级、括号、取反、引号/转义、空表达式、错误位置。

## 7. 运行环境约束（必须遵守）

- Windows 10/11 + PowerShell；Node v22.18.0、pnpm 10.29.1（通过 `pnpm.cmd` 调用；`.ps1` shim 被执行策略禁止）。
- 工作区沙箱只允许写工作目录内；pnpm 的 store/cache 已通过根目录 `.npmrc` 指向工作区内（`.pnpm-store` / `.pnpm-cache`），**不要修改 .npmrc 指向工作区外**。
- pnpm 10 默认阻止依赖构建脚本：`package.json` 的 `pnpm.onlyBuiltDependencies` 需包含 Prisma / esbuild 等（脚手架负责）。
- dump 数据 1.9 GB，**不得**提交进 git；`dump-db/`、`.pnpm-store/`、`.pnpm-cache/`、`node_modules/`、`.next/`、`prisma/*.db` 必须 gitignore。
- 所有 JSONL 读取按 UTF-8；Windows 控制台可能显示乱码，但文件内容本身是 UTF-8。
