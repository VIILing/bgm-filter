# Round 3 · 条目预览面板改版（原图封面 + 信息重排）

> 状态：已与用户确认方向，进入设计与实现。
> 上游：`docs/requirements.md`、`docs/ui-design.md` §2.12、`docs/cover-research.md`。
> 本文只描述「要什么、为什么、怎么判定完成」，不规定代码写法。

## 1. 背景与问题

列表为了多栏目展示，封面被压缩成行内小图，用户看不清画风，只能点进 bgm.tv 才能判断。当前悬浮预览面板（640px 宽）只有标题、简介、标签，没有封面，右侧半列仍被浪费。

**本轮目标**：让用户在预览面板里直接看到**未裁切、未放大的原图封面**，并围绕这张大图重排信息，减少跳转 bgm.tv 的次数。

## 2. 已确认的用户决策（2026-11-04）

| 决策点 | 结论 |
| --- | --- |
| 面板形态 | 保持右侧悬浮，宽度加到约 **880px**（窄屏按可用宽度收敛），覆盖列表右半部分 |
| 封面显示 | **按原图宽高比完整显示**；不裁边；小图不放大；超出面板时等比缩小 |
| 信息布局 | 上方信息区：**左封面、右标题/元信息/标签**；下方：简介 |
| 交付方式 | 先本地验收，**本轮不提交 GitHub**（HMAC 授权系统宕机，无需 PAT） |

## 3. 用户故事

1. 作为浏览者，我悬浮一行后能在面板左侧看到清晰的原图封面，判断画风。
2. 作为浏览者，我能在同一屏看到标题、类型/日期、评分等基本信息，不用再来回扫列表行。
3. 作为浏览者，我能在右侧直接看到该条目的标签与计数，快速判断题材。
4. 作为浏览者，我能在下方阅读完整简介，且滚动简介不会带动页面。
5. 作为浏览者，鼠标从行移到面板、或快速划过列表时，预览不会闪烁、错位或残留。

## 4. 功能需求

### 4.1 布局（桌面 ≥1024px）

```
┌──────────────────────────── 预览面板（约 880px，固定在右侧） ────────────────────────────┐
│ ┌──────────────┐  标题（日文原名，必要时两行）                          [类型] 2002-10-01 │
│ │              │  中文名（若有）                                    评分 8.7 · #1933   │
│ │   原图封面    │  ─────────────────────────────────────────────────                    │
│ │  （等比、     │  标签 10                                                            │
│ │   不裁切、    │  [科幻 1234] [赛博朋克 856] [押井守 412] …（换行，可滚动）             │
│ │   不放大）    │                                                                     │
│ └──────────────┘                                                                    │
│ ─────────────────────────────────────────────────────────────────────────────────── │
│ 简介                                                                                 │
│ 完整简介正文……（不折叠，内部滚动，滚轮不带动页面）                                     │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

- 面板仍用 `position: fixed` 贴右侧、顶部留出 Header 高度，**不跟随行上下移动**。
- 上区高度由封面决定；封面宽度以「原图自然尺寸」为上限，面板容纳不下时等比缩小。**不得为了填满而放大**。
- 右栏内容不得横向溢出；标题最多两行（超出省略），标签区超出时内部滚动。标签不可点击（避免误触筛选）。
- 简介区占据剩余高度，内部滚动；内容不足时留白，不撑破面板。

### 4.2 封面数据

- 使用 Bangumi 返回的 **`large`（原图）** 地址；该地址不含 `/r/` 缩放前缀，`<img>` 可直接显示，**不得**用 fetch/canvas 读取像素（无 CORS）。
- 原图地址必须进入现有封面缓存，避免每次悬浮都请求上游。缓存升级后**旧缓存条目也要能显示原图**，不允许要求用户手动删除 `.cache/covers.db`。
- 列表行内封面保持现状（继续用小图），本轮不放大列表封面、不改变列表密度。

### 4.3 状态与降级

| 场景 | 表现 |
| --- | --- |
| 原图加载中 | 封面区先占位（尺寸稳定），文字/标签/简介可先显示；不得出现布局跳动 |
| 原图加载失败 | 回退到已有较小封面；仍失败则显示「无封面」占位，不出现破图图标 |
| 条目无封面 | 固定比例占位 + 「无封面」，右栏信息正常显示 |
| 预览数据加载中 | 保持现有骨架/占位策略；不阻塞面板出现 |
| 预览请求失败 | 面板内提示「预览加载失败」，不影响列表与跳转 |

### 4.4 交互（保持不变的部分）

- `mouseenter` 行约 150ms 后打开，离开约 120ms 后关闭；指针移入面板保持打开。
- 同一时刻只显示一个面板；切换行复用缓存，快速划过不逐条请求。
- 面板内点击不跳转 bgm.tv；点击列表行其余区域仍跳转。
- 面板滚轮只滚面板内部，**绝不带动页面/列表**。
- `<768px` 不启用预览；触屏不启用。

### 4.5 响应式

- 1440 / 1280 / 1024 宽度下布局合理：面板不超出视口，封面与右栏不互相挤压变形。
- 1920 宽度下封面不超过原图自然尺寸，避免糊成大块。
- 面板宽度建议 `min(880px, 视口宽 - 安全边距)`；具体断点由设计稿确定。

## 5. 非目标

- 不做独立详情页、不做灯箱/点击放大（用户已选方案 A）。
- 不改列表卡片布局、不改筛选/排序/分页逻辑。
- 不引入新依赖（如需引入必须 Lead 确认）。
- 不改数据库主库 schema；只允许动封面缓存库。

## 6. 资源与性能影响（验收时需实测/核对）

| 维度 | 预期变化 | 说明 |
| --- | --- | --- |
| 网络 | 每次「首次预览某条目」多下载约 33–120 KB 原图 | 仅 hover 时加载；浏览器缓存命中后不再下载；不应对列表首屏造成负担 |
| 上游 API | 不增加调用次数 | `GET /v0/subjects/{id}` 本就返回 5 种尺寸；只是把 `large` 一并缓存 |
| 磁盘 | 封面缓存库每条多存一个 URL（约 100 B 级），可忽略 | 若缓存旧库需迁移，必须无损 |
| 前端 CPU | 无明显变化；大图解码略增，仅一张 | 必须限制同一时刻只显示一个面板 |
| 首屏性能 | 不应回退 | 列表仍用小图、原图只在 hover 后加载 |
| 服务器内存 | 无明显变化 | 无新增常驻缓存 |

> **实测回填（QA Round 3）**：原图单张实测 120,101 / 235,093 / 560,386 B（最大 1800×2500），高于上表 33–120 KB 的初始预估；仍只在首次悬浮时下载，暖缓存/重复悬浮为 0 请求，列表首屏仍只加载 25 张 `/r/200`（约 340 KB）。该差异作为已记录的资源取舍（`docs/qa-report-round3.md` P2-01），未改变实现。

## 7. 验收标准（QA 独立执行）

1. 1440×900：悬浮有封面条目，左封面完整可见、比例正确、无裁边、无放大；右侧标题/类型/日期/评分/标签完整；下方简介可滚。
2. 切换 3 个不同条目：封面、标题、标签、简介全部正确切换，无残影、无错位、无旧图残留。
3. 冷缓存与暖缓存各测一次：冷缓存文字先出、封面后到且不跳动；暖缓存即刻显示。
4. 无封面条目、原图 404/断网模拟：显示占位或回退图，不破版、不出现破图图标。
5. 简介区滚动到底：页面与列表不滚动；面板外滚轮正常滚页面。
6. 1280 / 1024 宽：面板不溢出、封面不变形、右栏文字不重叠；<768 不出现预览。
7. 点击面板不跳转；点击行左半区跳转 bgm.tv；关闭面板后点击行为正常。
8. 回归：筛选、排序、分页、行内封面、名称搜索均正常。
9. `pnpm test` 全绿、`pnpm typecheck` 0 error；涉及构建时 `pnpm build` 通过。
10. 证据：改版前后截图、尺寸/网络数据、逐条验收记录写入 `docs/qa-report-round3.md`。

## 8. 风险与待观察

- 880px 面板会盖住列表右半，切换行需在左半区悬浮；这是已确认的取舍。
- 原图尺寸差异大（有的很窄、有的接近方图），右栏宽度会随封面宽度变化；设计需给出最小/最大封面宽度与右栏最小宽度。
- 旧缓存迁移若处理不当会导致「升级后旧条目无原图」；列入 QA 必测。
- 大图在慢网下可能晚到；占位尺寸必须稳定，避免面板跳动。
